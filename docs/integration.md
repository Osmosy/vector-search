# Как использовать в конвейере решений

Правило одно: **на решение идёт только строгий путь**. Обычный поиск остаётся для
навигации и черновиков; всё, что влияет на решение, проходит журнал, чтение и гейт.

## Минимальный цикл

1. **Исследование.** `vsearch research "вопрос" --hits ...` (или DuckDuckGo без `--hits`)
   читает страницы строгим загрузчиком и пишет журнал: `final_url`, статус, тип,
   размер, sha256, время. Отказы тоже в журнале — 404 и капча это доказательство
   отсутствия материала, а не пустая строка.
2. **Досье.** Модель получает прочитанные тексты и возвращает JSON:

   ```json
   {
     "questions": ["сколько стоит подписка"],
     "claims": [{
       "id": 1,
       "text": "годовая подписка стоит 1 999 ₽",
       "source_ids": [3],
       "quote": "Годовая подписка — 1 999 ₽",
       "numbers": ["1999"]
     }],
     "sufficiency": {"answered": true, "gaps": [], "next_queries": []}
   }
   ```

3. **Гейт.** `vsearch check dossier.json --ledger data/ledger.jsonl --receipt receipt.md`.
   Код `0` — досье раскрыто; `1` — есть утверждение без цитаты, число не из текста,
   вопрос без утверждения или противоречие в оценке достаточности.

## Что именно проверяется

- Номера источников существуют и прочитаны (не 404, не капча, не скан).
- Цитата встречается в тексте дословно, минимум три слова с буквами.
- Числа утверждения есть в тексте источника по значению: `1 999`, `1,999` и `1999` —
  одно число, `47.4` и `47,4` — одно, `50` против `47,4` — расхождение.
- `answered=true` не сочетается с непустыми `gaps` и с отсутствием утверждений;
  `answered=false` требует названных пробелов.
- На каждый вопрос есть утверждение, в котором присутствуют все значимые слова
  вопроса (без стоп-слов).

## JS-страницы

Если HTML отдал оболочку (текст меньше 400 символов или маркер «please enable
JavaScript»), сначала читается встроенный JSON страницы (`application/ld+json`,
`__NEXT_DATA__`) — это те же значения, что опубликовал сайт, без подстановок
браузера, `provider: embedded-json`. Если его мало, страницу надо рендерить:
`vsearch fetch URL --browser` или `allow_browser: true` в инструменте плагина.
Текст из браузера проходит те же проверки и попадает в журнал с `provider: browser:bsk`.

## Независимость критичных чисел

Утверждение с `"critical": true` требует, чтобы каждое его число подтверждалось
двумя **независимыми доменами**: `a.example.com` и `b.example.com` — один домен
(`example.com`), `example.com` и `other.org` — два.

Критичность выводится сама по единицам числа: ₽, $, €, руб., %, ‰, мг, мл, дней,
часов, месяцев. Модель может переопределить её полями `"critical": true` или
`"critical": false`; во втором случае при критичной единице гейт выдаёт
предупреждение, потому что понижение критичности — решение, а не случайность.

## Оценки без числа

«Существенно дешевле», «в разы быстрее», «примерно столько же» — не проверяемо.
Утверждение с такой формулировкой и без чисел получает отказ: раскройте числом или
уберите формулировку. Если число есть, но рядом стоит «примерно», «около», «почти»,
гейт выдаёт предупреждение: сверка идёт с допуском 0,1 %, и округление в него не
укладывается.

## Плагин Hermes

`integrations/hermes-plugin/` регистрирует `vsearch_fetch`, `vsearch_check` и
`vsearch_status`; агент вызывает их вместо обычного чтения, когда факт идёт в
решение. Успешный ответ не содержит ключей `"error"`/`"failed"` — иначе Hermes
помечает вызов сбоем (`_detect_tool_failure`), хотя данные получены.

## Товары

`vsearch products --source ID --strict` разбирает предложения и сверяет название,
цену, валюту, наличие и характеристики (`Память: 256 ГБ`) с текстом страницы.
Ответ собирается только из прошедших проверку строк; отклонённые печатаются с
причиной. `--strict` возвращает ненулевой код при любом отклонении.

## Границы

Гарантируется трассировка, а не истинность источника. Для критичных чисел —
правило двух независимых источников. Логика вывода проверяется дисциплиной
«утверждение = цитата + арифметика», а не этим инструментом. Антибот и платный
контент не обходятся: это отказ.
