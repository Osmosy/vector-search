# vector-search

Проверяемый поиск: каждое утверждение, на котором принимается решение, раскрывается
до байтов источника — адрес, время получения, HTTP-статус, тип содержимого, хеш
текста и дословная цитата.

Принцип один: **fail-closed**. Если утверждение нельзя раскрыть до источника — оно
не попадает в ответ. «Вероятно», «похоже», «примерно» не считаются результатом.

## Зачем

Обычный поиск возвращает сниппеты и тексты, но не даёт ответить на три вопроса:

1. Существовала ли страница в момент, когда на неё сослались, и что именно в ней было?
2. Есть ли в тексте страницы то число и та цитата, которые попали в вывод?
3. Достаточно ли источников, чтобы считать утверждение подтверждённым?

Поэтому журнал источников, строгое чтение и гейт проверки — часть инструмента,
а не пожелание в инструкции.

## Что уже работает (0.5.0)

- `vsearch/ledger.py` — журнал источников: id, финальный URL после редиректов,
  время получения, статус, тип содержимого, размер, sha256 текста, провайдер,
  цепочка редиректов, ошибка. Тексты хранятся рядом, целостность проверяется хешем.
- `vsearch/numbers.py` — нормализация чисел (разряды, запятая/точка, знак, валюта,
  проценты, единицы) и сверка чисел утверждения с текстом источника.
- `vsearch/claims.py` — структура утверждения (текст, номера источников, дословная
  цитата, числа) и её валидация: номера существуют, цитата есть в тексте дословно,
  числа присутствуют в источнике.
- `vsearch/verify.py` — гейт: покрытие утверждений доказательствами, обязательные
  цитаты, квитанция «утверждение → источник → цитата → хеш → время».
- `vsearch/fetch.py` — строгое чтение: только http/https, блокировка приватных
  адресов и адресов облачных метаданных, ручные редиректы с проверкой каждого хоста,
  whitelist типов, лимиты байт и времени, минимальная длина содержательного текста.
- `vsearch/extract.py` — HTML в текст без скриптов и стилей; PDF через `pdftotext`
  с проверкой, что текстовый слой есть (скан не превращается в пустоту).
- `vsearch/browser.py` — рендер JS-страниц через `bsk` (browser-skill): если HTML
  отдал оболочку или текста меньше порога, страница открывается в браузере, а текст
  идёт в тот же журнал с тем же хешем. Браузер подключается явно (`--browser`).
  Раньше браузера включается разбор встроенного JSON (`application/ld+json`,
  `__NEXT_DATA__`): значения приходят ровно те, что опубликовал сайт, и помечаются
  `provider: embedded-json`.
- `vsearch/search.py` — выдача без текста страниц: провайдер отдаёт ссылки и
  сниппеты, текст приходит только строгим чтением. Есть DuckDuckGo (без ключа) и
  статическая выдача из файла для офлайн-прогонов.
- `vsearch/research.py` — раунды «поиск → выбор → чтение → чего не хватает → новые
  запросы» с жёстким бюджетом: 4 раунда, 16 чтений, 60 с на страницу. Исчерпание —
  отчёт «данных недостаточно» со списком пробелов, а не ответ по догадке.
- `vsearch/products.py` — товарная сверка: название, цена, валюта, наличие и
  характеристики (`Память: 256 ГБ`) сверяются с текстом блока; ответ собирается
  только из прошедших проверку строк, отклонённые печатаются с причиной.
- `vsearch/dossier.py` — досье ответа: вопросы, утверждения и оценка достаточности
  проверяются как структура. Ловятся противоречия (`answered=true` вместе с
  пробелами, `answered=false` без пробелов) и вопросы без утверждений.
- `vsearch/domains.py` — независимость источников: два URL одного сайта — одно
  подтверждение. Критичное число требует двух независимых доменов.
- `vsearch/numbers.py::critical_reason` — критичность выводится по единицам: деньги,
  проценты, дозировки, сроки (₽, $, €, %, мг, мл, дней, часов…). Модель может
  указать `critical: true/false` явно; если указала `false` при критичной единице,
  гейт выдаёт предупреждение.
- `vsearch/cli.py` — команды `fetch`, `research`, `check`, `verify`, `products`, `numbers`.
- `integrations/hermes-plugin/` — плагин Hermes: `vsearch_fetch`, `vsearch_check`,
  `vsearch_status`. Установка и контракт ответа — в README плагина.
- `docs/integration.md` — как встроить в конвейер решений: цикл, формат досье,
  что именно проверяется и какие границы у инструмента.

## Чего ещё нет

- Сетевые тесты выключены по умолчанию: `VSEARCH_NETWORK=1 uv run pytest -m network`,
  отдельный workflow `network.yml` запускается вручную.
- Обхода антибота и платного контента нет и не будет: это отказ.

   (`looks_like_captcha`, тесты в `tests/test_extract.py`).
3. Исследование с бюджетом: 4 раунда, 16 чтений, 60 секунд на страницу; исчерпание
   бюджета — отчёт «данных недостаточно», а не ответ по догадке. — сделано.
4. Проверка утверждений и достаточности: досье проверяется как структура, включая
   противоречия в оценке, покрытие вопросов и независимость источников для критичных
   чисел; критичность определяется по единицам, а не только по слову модели — сделано.
5. Числовая и товарная сверка: числа, цена, валюта, наличие и характеристики,
   сборка ответа из проверенных строк — сделано.

   `vsearch_check`, `vsearch_status`.

## Установка и прогон

```bash
uv sync
uv run pytest
uv run vsearch --help
```

Строгое чтение одной страницы (JS-страницы — с `--browser`):

```bash
uv run vsearch fetch https://example.com/article --ledger data/ledger.jsonl
```

Исследование с бюджетом (офлайн-выдача из файла, чтобы прогон был воспроизводим):

```bash
uv run vsearch research "open source license" --hits hits.json --rounds 2 --fetches 3
```

Товарная сверка по источнику из журнала:

```bash
uv run vsearch products --source 2 --strict
```

Досье ответа (вопросы + утверждения + оценка достаточности):

```bash
uv run vsearch check dossier.json --ledger data/ledger.jsonl --receipt receipt.md
```

Проверка утверждений:

```bash
uv run vsearch verify claims.json --ledger data/ledger.jsonl --min-coverage 1.0
```

Код выхода `0` — все утверждения раскрыты до источников и цитат; `1` — есть
непроверенное утверждение, и в выводе назван его номер.

## Ограничения

- Гарантируется трассировка, а не истинность источника. Если вендор написал неверное
  число, квитанция будет безупречной. Для критичных чисел — правило двух независимых
  источников.
- Проверяются цитаты и числа, а не логика вывода.
- Антибот и платный контент не обходятся: это отказ, а не подмена источника.
